## 2026-11-07 更新：真实模型计划管线

新建档案和计划页的 AI 入口使用 `deepseek-v4-pro`、高思考模式：完整草案 → 独立模型评审 → 最多两次修正与复评 → 程序硬约束 → 用户预览采用。两个角色为独立调用，不以规则分数冒充模型评审；阈值80是产品审核线，不是医学认证。任务按账号后台运行，可关闭后查看真实阶段；失败保留旧计划，不回退并冒称模型生成。

档案支持目标/运动/器械补充、专项与竞技背景、每周7个可用日和10–240分钟预算；可用日不等于每天必须训练。缺基线仍说明假设与问题，不猜工作重量。演示和旧API保留基础模板兼容；它们不等于新模型管线。

模型输入包含必要档案、既有计划与训练反馈；不发送邮箱、姓名、平均心率或经期按钮数据。原始模型思维文本不展示或保存，页面展示可核对的方案依据、评审问题与修正结果。预算按配置单价保守估算，可按供应商账单校准。

# SportsWise · 找到自己的运动节奏

从你的运动现状、目标和生活安排出发，制定第一周试行计划；根据反馈调整，在日、周、月的跟进中逐渐认识自己、建立规律。

已部署：[sportswise.waywise.tech](https://sportswise.waywise.tech)。本地地址 http://127.0.0.1:8500。开发数据库和凭据不进入版本控制；线上使用独立服务与数据库。

## 已实现

- 手机与桌面适配的「今天 / 计划 / 成长 / 我的」，从零试用与含四周虚构记录的示例空间相互独立。
- 邮箱验证码登录；本机开发且未配置 SMTP 时，仅本机请求返回开发验证码，生产环境不开放此回退。
- 自然语言整理档案后逐项核对，目标、现状、兴趣、器械、可用日期与时间、身体限制。
- 个性化训练路线：根据目标、运动水平、可用日、常规训练时长、运动偏好、场地和器械，安排有氧、跑走、跑步、骑行、力量与恢复活动。规律训练者可获得中等强度课程和 A/B 力量安排；每节课含热身、主体和收尾。
- 「今天」与「我的」提供可选的经期调整：照常、减量、休息；只作用于所选日期内未记录的课程，跨周生效、到期自动恢复，也可提前结束。经期状态不会发送给模型或出现在邮件中。
- 中文对话修改和快捷修改：缩短、本周减量、室内替换、周内改期、休息、重新开始；草案预览、用户采用、版本和撤回。
- 实际训练计时、完成 / 部分完成 / 未完成 / 休息反馈，自主活动记录，重复提交按训练 ID 更新。
- 原始计划 / 当前计划 / 实际活动分开统计，未记录不等同于没完成。
- 成长页首屏可记录计划外活动，支持选填和更正平均心率。周、月回顾随实际记录更新，提供运动量、值得肯定的进展及下一步建议。不同活动会点亮运动花园的对应景物，部分完成也计入。
- 周月复盘、下一周草案、明确恢复确认后的有限进阶。下一周采用后排队，到新周才自动接上；未提前规划时，新周保守延续或减量，不自动进阶。
- 每 30 秒扫描的持久化站内提醒、可选 SMTP 邮件、日 / 周 / 月 / 未记录跟进、安静时段、时区、暂停和跟进语气。
- 导出 JSON、账号及关联数据删除、来源隔离、同源校验、会话保护、过期草案和多页面版本冲突检查。
- AI 调用记账、预算预留、每日限制；模型不可用时回退到有限的规则解析，并在界面注明。

## 本地运行

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8500
```

不配置密钥可体验已有示例与基础规则调整。配置 `DEEPSEEK_API_KEY` 后启用自然语言档案整理、对话理解和模型训练计划。新档案入口保存资料后提交后台任务，习惯/日常体能等简单档案默认由 `deepseek-flash` low 编排与独立评分；增肌、专项、进阶、保留结构或复杂限制档案由 Pro low 编排和复评，出现必须修正项时升级 Pro 修订，最后一轮才启用 high。程序校验与评分门槛不变，按反馈最多修正两轮；通过程序校验且独立评分通过后，才可预览采用。失败保留原计划，不使用规则模板冒充模型输出。`MODEL_NAME`、`DEEPSEEK_BASE_URL` 及估算价格可配置，需使用供应商当前支持的模型。价格字段用于记账估算，不代表供应商账单。

本地 `.env` 已接入 AI。生产环境经用户明确授权复用 InvestWise 的模型与 SMTP 配置，SMTP 登录已验证，未发送测试邮件。不要将 `.env` 上传仓库。从零试用资料可在首次注册时由用户选择保存，示例历史绝不混入正式账号。

## 数据和生成边界

档案、计划、实际反馈、复盘和对话保存在 SQLite 的每用户状态中；用户输入作为数据使用，模型不能执行 SQL 或绕过计划校验。提醒、邮件状态、会话、验证码、草案和用量各有独立表。

新入口由模型生成实际训练内容，确定性模板保留给演示和旧版流程；程序检查时长、恢复间隔和安排冲突。生成模板参考公开的 NHS、NIDDK 和 CDC 一般活动资料；经期功能按主观感受临时调整，参考 [ACOG 经期疼痛资料](https://www.acog.org/womens-health/faqs/dysmenorrhea-painful-periods)与[运动表现系统综述](https://doi.org/10.1007/s40279-020-01319-3)；**尚未完成运动专业人士的内容审核**，不能称作已获专业认证的训练处方。首版不提供康复、疾病、孕产或竞技专项方案。身体情况以注意事项和轻量约束纳入计划，普通体检指标异常不阻止生成；急性异常或明确停止运动医嘱时，生成恢复与确认安排，暂停主动训练建议。旧版因非空身体情况而拦截的档案，访问时会自动补出方案。

数据传输应使用 HTTPS。当前没有端到端加密：服务端可读取必要记录。调用 AI 时发送必要档案、当前周计划、近期记录及最近对话；档案整理按钮旁会说明发送行为。提醒邮件不包含训练细节或健康信息。账号删除同步删除本服务数据和用量身份；供应商留存及部署方备份不受该操作直接控制，正式上线前应明确其处理规则。

## 提醒行为

服务进程持续运行时，后台扫描按用户时区执行：

- 训练提醒仅在设定时间后两小时内创建，休息日、已记录训练不创建。
- 用户启用未记录跟进时，在后两小时窗口跟进一次。
- 周一回顾上一周；每月一日回顾上个月。服务关闭期间不运行，不在恢复后补发过期日提醒。
- 安静时段、暂停、身体建议暂停和两周未访问会抑制主动提醒。
- 计划或设置变更会取消尚未发送的旧任务，发送前再次检查用户设置。
- 数据库唯一键抑制重复生成；SMTP 超时可能意味着已经送达，标记为“结果未确认”，不自动重发。
- 不把“已发送”视为“用户已看到”。演示账号不会发送邮件。

本机预览随电脑和服务进程运行。需要全天提醒时，在服务器上用 systemd 持续运行。

## 身体情况与生成策略（2026-11-01 更新）

一般健康风险仍生成训练计划，并在计划页面、调整草案、训练开始前展示遵医嘱提醒，初期使用较轻量安排，风险未明确前不自动进阶。身体情况字段不是医学诊断，关键词仅用于保守的产品分流，不证明活动对个体安全。

出现急性异常、明确停止运动或卧床等限制时，仍提供有结构的恢复与确认计划，暂停主动训练；不使用一条免责声明绕过已知限制。现阶段年龄适用范围与数据保存同意仍需确认。

参考：[NIDDK：从少量活动开始并结合健康专业人士建议](https://www.niddk.nih.gov/health-information/weight-management/tips-get-active/tips-starting-physical-activity)、[Newcastle Hospitals：异常症状与暂停运动](https://www.newcastle-hospitals.nhs.uk/services/newcastle-occupational-health-service/information-for-staff/physiotherapy/self-help-leaflets/exercise-and-your-health-a-guide-to-getting-started/)。

## 速度、费用与等待预估

生成前的 `/api/planning/estimate` 与后台任务返回同类调用的估时区间、已耗时和样本依据，包含已知排队；修订发生时明确延长，超过预估时提示仍在处理，轮询不会重置倒计时。开始后的预估保存在任务内，页面关闭和跨设备查询仍可恢复。

`llm_usage` 额外记录实际模型、推理强度、耗时、token和成功/截断状态，既有预算/账号额度继续生效。按模型配置人民币保守估算价，不等同供应商账单；缓存折扣未抵扣。独立评审仍审查完整七日与完整档案，数学/器械/恢复硬约束不因切换模型放宽。最终草案记录实际生成模型与复评模型，而非固定标成Pro。

用户已采用且仍适配的已评审训练框架，在选择保留结构时按周滚动日期并定点调整；旧评分不沿用。改目标、缩短全局时长、改变可用日、出现新的风险限制或要求从头制定时，重新编排。
