# 模型效率与等待体验

## 最终策略

- 习惯建立、日常体能等低复杂度档案：Flash low生成与独立复评。
- 增肌、专项、进阶、高频、保留训练结构或身体限制等专业编排：Pro low生成与独立复评。
- 第一轮未通过：Pro low定点修订；最后一次仍需修订时才提高至high。
- 已采用且仍适配的AI计划，保留结构时先滚动周日期，再按本次要求和实际反馈定点调整；旧评分不沿用，整周重新校验和独立评分。目标、全局时长、可用日、风险变化或要求从头制定时，重新编排。
- 日常记录和提醒继续用程序完成，不调用重模型。结构化档案整理和意图识别仍为短请求。

不默认采用非推理起草：规律增肌者对照首评71，完整流程发生返工；简单档案非推理起草虽27秒，仍没有在测试中完成达标交付。模型更便宜或第一步更快，不代表整套流程更快更便宜。

## 等待与费用

生成前显示估时区间；开始后显示已耗时，保留后台运行。排队计入估时；真实出现修订/升级时延长并解释；超时显示仍在处理，不重置倒计时或显示虚假百分比。

估计优先匹配近期同任务、模型和推理档位的实际耗时。样本不足时明确标注初步估计；实验调用不混入正式用户分布。当前冷启动完整计划约1–5分钟（简单）或2–6分钟（专业），修订可能延长，不是交付保证。后续可由真实分布校准。

`llm_usage`增加模型、推理强度、耗时和成功/截断状态，记录实际token。原有每日预算和账号额度保持生效。人民币费用是配置的保守估算，不是供应商账单；未抵扣缓存优惠。

## 真实测试结果与限制

本次采用虚构档案，不修改真实账号计划、不发邮件。完整原始汇总见同目录`模型路由实测-2026-11-08.json`。

| 对照 | 结果 |
| --- | --- |
| 规律增肌，Flash low起草 | 起草145秒，首评84未通过；完整Pro修订后99分通过，合计396秒 |
| 进阶混合，Flash low起草并升级 | 仍未通过；此分支未作为复杂计划默认路线 |
| 规律增肌，Flash非推理起草 | 起草49秒，首评71未通过，停止该低质量分支 |
| 规律增肌，Pro low完整起草 | 起草104秒，首评89但程序校验发现缺项；后续评分服务返回不完整。未伪称通过 |
| 简单习惯，Flash low起草+按需修订 | 最终91分通过，合计373秒，存在两次修订 |
| 已评审增肌结构，定点换一个动作 | 修订18.8秒+完整Pro low复评78秒，合计96.8秒；88分、程序校验通过 |

以上是少量样本，不证明任一模型在所有人群中效果等同，也不能把19秒修订时间当成全流程时间。测试暴露的默认空字段、定时静力保持强度表达及局部修订格式兼容问题已修复；未降低评分或器械/时间/恢复检查来获得通过。
