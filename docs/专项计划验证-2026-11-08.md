四例覆盖一般新手、规律者、进阶和竞技专项的不同边界，**不等于每个项目所有水平、伤病、性别、年龄均验证完成**。后续应扩展篮球/羽毛球/标枪各自的零经验与进阶对照、没有教练/场地、赛季未知、密集比赛、局部限制等矩阵。

四例先通过产品真实 `app.main.Profile.model_validate(...).model_dump(mode='json')` 规范化后再运行，不绕过可保存档案的枚举与长度约束。篮球/标枪使用 `likes=['other', ...]` 加 `activity_detail`；球场、跑道及标枪用 `equipment=['other', ...]` 加 `equipment_detail`；健身房展开为确有的杠铃/架/凳/哑铃/拉力器等。没有使用额外 `sport` 字段，专项识别来自用户实际能填写的文字。导出及运行均拒绝产品未定义字段，防止Pydantic默认忽略extra造成假测试。

## 专项100分审核与必修红线

沿用已有八维总分，但把“覆盖”解释为专项需求，而不是一律追求每肌群增肌组数：目标20、剂量与覆盖20、起点15、可执行细节15、恢复10、偏好可行性10、反馈进阶5、透明度5。

- 目标20：项目、位置/单打双打、具体短板、赛季和比赛优先级；辅助训练如何服务目标。没有真实专项内容却称完整专项处方，不能因文案长而高分。
- 剂量20：技术/战术/辅助体能/比赛分开且合并已知负荷；爆发、间歇、力量使用正确剂量单位，不能只数健身工作组。对标枪，未授权指定投掷负荷属于必修，不为“完整度”补造数值。
- 起点15：专项年限与抗阻、跳跃、冲刺、投掷等基础分别判断；基础不足的具体领域校准，不按advanced标签假定所有复杂动作熟练。
- 细节15：逐动作、轮次、左右侧、休息和转场可执行；技术课由教练管理时保留边界，既不捏造教练细节，也不把“听教练”当整份体能方案。
- 恢复10：连同场上课、比赛、局部关节组织与实际强度评估；低量技术和支撑肌不能机械当直接大负荷，但高负荷也不能伪标skill逃避审查。
- 可行性10：球场/投掷区/器械、主教练日程、合计时间，提供同目标替代；不能在不适合场地独自真枪投掷。
- 进阶5：依据课后反馈、动作质量、表现和恢复调整；不按日历自动加投掷量、冲刺量或极限负重。
- 透明5：具体来源、来源等级、假设与待确认项、当前是完整方案还是辅助/校准，并说明会改变安排的信号。

以下任一项未解决，即使模型给80分以上也必须列 must_fix：

1. 编造1RM、阈值心率、出场时间、投掷量/强度/器械、比赛场数等个人事实。
2. 违背明确禁练、可用日或时间预算；规定剂量按轮次/休息/每侧计算实际塞不下；爆发课疲劳逻辑与质量停止条件明显矛盾。
3. 无视已给的专项课/比赛负荷，宣称完整整周合理；赛前额外疲劳刺激没有与既有安排协调。
4. 标枪无基线/教练确认安排高强度或全助跑投掷，或者药球替代被称为标枪技术；无安全场地却安排实际投掷。
5. 目标核心内容缺失却宣称完成：如只有通用增肌称“标枪完整专项计划”，或辅助课未纳入既有球场负荷却称“完整篮球赛训周”。

缺少次要文字润色、可能可选的更多动作、尚未提供的非关键测试结果不自动必修。缺关键数据仍应给有明确边界的可执行辅助方案，不能无条件拒绝生成全部内容。

## 运行方法及预算

仅导出四例档案、知识、人工核对清单，不发起API请求：

```sh
.venv/bin/python scripts/evaluate_sport_plans.py --week 2026-11-09 --output /tmp/sportswise-sport-fixtures-20261108
```

由主 agent 在获授权的服务器临时应用副本中统一执行真实流程：

```sh
.venv/bin/python scripts/evaluate_sport_plans.py --run --cases beginner basketball badminton javelin --week 2026-11-09 --max-calls 8 --output /tmp/sportswise-sport-real-20261108
```

默认全局上限8次；先为每例保留生成+独立评审各一次，剩余配额才允许修订。单例可用 `--cases javelin --max-calls 4` 做一次修订后复评，最多支持总上限24次及管线原有两轮修订。到限不会重试网络；病例如无完整生成+评审预算会标 not_run，绝不当作通过。失败草稿和评审同样保存，不丢问题。

真实路径为 `planning_policy.route → services.planning_model_json → ai_planning.pipeline`，使用 `state.explanation_policy=True`、`compact_revisions=True`。每次真实调用按现有模型路由及 `llm_usage` 保守预留/实际估算记账，遵守配置的全局每日金额与账号调用数上限；同一批四例共用一个虚构actor，不分拆actor绕过限制。上限是调用数，不保证金额可承担；金额上限仍由services控制。临时应用副本**应指向主 agent 指定的同一预算账本**；不可复制/重置账本或临时调高每日预算来绕过累计用量。脚本不调用 `db.init()` 或后台worker，不创建用户/任务、不采纳计划、不发送邮件。

每例保存 `input.json`、完整每次模型messages/output/metrics、`result.json`、`events.json`。默认独立 `/tmp/sportswise-sport-eval-<随机值>`；目标必须不存在，防止混入旧稿；目录0700、文件0600，不含密钥和模型隐藏推理。`summary.json` 包括代码哈希、配额、真实得分/必修/结构问题，明确 `needs_human_sport_review`。必须读取完整动作原稿和checklist核对；不能只把summary里的分数当结论。

## 当前实证与未覆盖缺口

- `tests/test_sport_planning.py` 的12项离线检查通过：真实Profile规范化及禁止静默丢字段、专项来源选择及去重、成人不套青少年资料、自由文字识别、标枪红线、离线无DB/API/邮件、跨案例总调用数、保留四例独立评审配额、结构错误不能被99分绕过、完整输出落盘与权限。与现有管线测试合计55项通过。仅代表工具和筛查合同正确。
- 本轮早期恶意stub诊断发现：当时管线可能接受calibration全周rest配合99分/通过的模型评审，尤其habit/performance缺乏结构上的目标最低内容校验。主 agent 随后补了健康档案未要求全周休息时的阻断；这不是本轮真实模型生成全休息的证据。
- 单日单课程/固定minutes schema 不能完整表达“90分钟既有球队课+30分钟额外辅助”的一般情形；本次用明确合计预算规避档案本身冲突，但产品仍需外部负荷字段和与教练课协调的独立评审，不能因此宣称缺口已经解决。
- 当前规则可看动作肌群与强度，但并不能仅靠主要肌群推断投掷、连续跳跃、急停和比赛的组织负荷；未知RPE和局数不能伪造填满。涉及真实专项技术、疼痛与赛季峰值策略仍需专项教练核对。
- BWF当前完整教材没有获取，且四例不是完整人群矩阵。实测具体差错见下节，不把已有分数当成“专项合理”的结论。

### 标枪：必须修复

1. **不能只照模型评审建议加到6/7分钟。** `tempo='2-1-1'` 是4秒一次，模型/程序以默认3秒漏算；下列最低时间按每侧、两侧均完成后休息、仅组间休息、setup30秒算，尚未加额外换侧：

   | 日期/动作 | 实际剂量 | 最低时间 | 原分配 |
   |---|---|---|---|
   | 11-09 Pallof按压 | 3×10/侧，4秒/次，休60秒 | 240+120+30=390秒，6.5分钟 | 5分钟 |
   | 11-13 面拉 | 3×15，4秒/次，休60秒 | 180+120+30=330秒，5.5分钟 | 5分钟 |
   | 11-13 肩袖外旋 | 3×12/侧，4秒/次，休60秒 | 288+120+30=438秒，7.3分钟 | 5分钟 |

   独立模型只报Pallof与外旋，漏了面拉；其建议6分钟和7分钟仍不够。必须统一节奏文字和结构化秒数后重新核对全部动作，不缩短节奏刷过审。分腿蹲、单腿RDL的3-1-1、引体的3-1-1及划船2-1-1也需统一字段；这些动作按原分配大体装得下，但不能保留错误计时。原稿周一45分钟步骤和42、周五45分钟步骤和38，管线仅同步总时长，未解决组内真实时间。
2. 档案写熟悉RDL，不等于熟悉**单腿RDL**；原稿assumptions无条件声称熟悉单腿RDL，又新增“反向跳接分腿落地”3组×2/侧（12次落地），没有给该动作的实际熟练与负荷基线。应先具体确认，或采用已熟悉版本；复杂单脚落地需教练确认/质量学习分支。不能把专项6年当所有爆发动作熟练，也不应因此把整个运动员退为新手。
3. 周五3组引体+3组单臂划船+3组面拉+3组外旋均RIR3，周六是投掷课。未知投掷强度/量时，不能仅因“拉力、肩袖维护”就断言不干扰或保证不冲突。它们也会给肩带带来训练负荷。与主教练确认后再决定保留/减量/移日，给未确认前的低疲劳分支；不机械强制每组都轻或一刀切48小时禁练。
4. 主教练技术课虽保持总75分钟，却被自行细分成12分钟热身+50分钟投掷技术+13分钟恢复；助跑课也被分成8+30+7。用户只确认整课时间，内部切分应标为待教练确认的预留，不是已知处方。保留技术课不得以满足schema为由强迫模型推定投掷是低负荷。`skill`在当前确定性恢复里被豁免，但真实投掷未必低负荷，需要“外部教练管理、强度未知”的明确标记与独立评审。
5. “辅助计划保证不冲突”、以WA概览支持“删除推压/拉力即可保护肩肘”等表述过强。可以作为个体待确认的编排选择，不能说成来源证明其个人安全或康复效果。静息心率连续3天高5bpm也仅能作为结合个人基线的观察示例，不是已验证的个人阈值或单独医学判定。

正面证据：没有捏造投掷次数、百分比或器械重量，没有药球冒充标枪；明确询问主教练负荷、赛季与恢复；确实区分技术与辅助体能。这支持继续改进这条路线，不支持已经形成合格竞技标枪处方。

### 羽毛球：必须修复与评审自身问题

1. 周一四个动作详情均写3秒下+1秒上，却给 `tempo_seconds=3`，必须同步4秒再算。分腿蹲2×8/侧：128秒工作+75秒休息+30秒setup=233秒，原4分钟只余7秒给未显式计入的换侧；应明确换侧/休息定义，必要时增加分配时间。RDL、双臂划船和双脚提踵按4秒计算仍可在各3分钟内完成，不能把“所有动作都必然超时”写成结论。
2. 周六强度写RPE7或以上的正式比赛，却把主体标 `block_type='skill'`。比赛不能被当低负荷技术学习而跳过整体负荷意义；主动力肌群留空也不代表比赛对下肢和肩带无负荷。用外部比赛/间歇的诚实表达、记录实际赛程及强度，不能为过校验降成低RPE。
3. 原稿把90分钟预留分成10热身+70比赛+10冷身，但实际局数/赛程未知。70分钟只能是预留窗口，不是可控制的固定比赛剂量。需给赛程更长、额外场次、恢复差时与教练协调及缩减辅助的条件；assumptions与programming里“未知赛程不影响力量剂量选择”过于绝对。可保留当前低容量起点，但应视整体负荷调整。
4. 周二/四教练课只用单一move、没有显式热身收尾；可注明由教练负责且计入已知整课时长，不能补造击球/多球次数来装完整。保留课缺 `rationale/progression_rule`，应解释“为何保留”和“何时反馈教练/减少额外训练”，无需越权给比赛自动进阶处方。
5. 评审总分78，但八维分数相加为87，未说明封顶原因；这份评分自身也需纠正。评审一方面在说明中知道周六有热身冷身，另一方面将三堂保留课一并说成单一move，存在过度概括。其要求正式比赛满足“低负荷强度”不能直接照做，应区分外部高负荷比赛与技术学习。

正面证据：仅周一给分腿蹲、RDL、划船、提踵2×8 RIR3；保留双打、右手持拍、固定教练/搭档课与周六赛，未额外堆跳杀与长跑。仍缺更有依据的持拍侧/肩带个体差异评估，但不能为了“专项”而在比赛周强塞新动作。

### 篮球：完整草稿已读，尚无独立模型复评

1. 保留周二/四75分钟球队课与周六90分钟比赛、约25分钟出场是正确使用已提供事实；周一四个熟悉主项3×5 RIR3、周五20分钟低量准备，有赛中维护而非通用增肌逻辑。
2. 必修执行措辞：回退规则写“降低RIR至4”，而RIR3→4实际是提高余力、降低相对努力；应直接写“降低重量/提高余力至4”。“力量量减半（如2组）”也不准确，3→2组是减约三分之一。用户照做时不能产生相反理解。
3. 周五新增反向纵跳2×3，虽量小、非最大高度且停止条件具体，仍应确认此前已有跳跃激活经验/教练同意；原档案“不额外增加冲刺跳跃课”需区分是否接受这项激活，不能默认同意。后续“启动慢可加一组、总时长25分钟”违背原周五20分钟约定；应维持既定上限并由实际反馈与主教练共同决定，不按一次主观唤醒不足自动加跳。
4. 动态准备只有一般关节活动，主项没有明确轻重量递增准备；应把必要热身、换重量和安全保护安排入时间。鸟狗“保持2秒”与完整伸/收周期未统一计时；Pallof也有保持说明，应完整核对，不能假定只数静止时长。
5. 球队课与比赛整堂一个move虽文字包含热身/放松，结构未表达；应让模型忠实承认外部负荷管理，而不是给90分钟比赛强行编固定轮次。RDL的 `lower_back`不在当前词表是格式问题，可正确映射back/稳定肌群；不能由此删掉真实躯干负荷。
6. 程序把纵跳“速度下降即停”的明确停止条件判缺失，是停止措辞识别不足的误杀；不应要求删除真实安全条件来过审。篮球/羽球被判未明确限制，源于档案否定句“目前无疼痛或明确运动限制”的解析，原生成上下文risk=caution；这不是有真实伤情的证据。

### 结果如何用于下一步

本轮结论是**存在专项差异化能力，但没有任何一例获得可采用的完整通过结果**。标枪86分仍有必修且漏项，羽球78分及分项算术不一致；篮球评审未运行，新手无完整生成。上述原始结构发现对应manifest中的代码快照，不代表修复后的代码仍有完全相同误杀。

在本次人工报告后，主 agent 已修复数字节奏2-1-1与显式秒数的时间下界校验/规范化、否定限制短语误判、锁定历史课误套新档案时间预算的问题，并报告139项Python与25项JS检查通过。**这些是代码与离线检查进展，修复后的专项真实模型复测仍待做。** 原稿中的动作熟练假设、外部负荷、比赛标签、恢复承诺和评分自检等问题仍需逐项处理，不能因修复计时程序就判旧稿合格。
